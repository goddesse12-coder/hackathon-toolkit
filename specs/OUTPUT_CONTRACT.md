# 산출물·근거 규격

이 규격은 기본 기록 방법이다. 문제에서 지정한 파일명·스키마·분량·제출 경로가 우선한다.

## 요구사항 연결

| ID | 원문 요구사항 | 충족 파일·위치 | 확인 방법 | 상태 | 근거 |
|---|---|---|---|---|---|

상태는 `통과`, `실패`, `미검증`, `해당없음` 중 하나를 사용한다. 해당없음에는 이유를 붙인다. 계획한 검증과 실제 실행한 검증을 구분한다.

## 주장과 수치

- 사실: 확인 가능한 원본 위치를 연결한다.
- 추론: 근거가 되는 사실과 추론의 한계를 표시한다.
- 가정: 왜 필요한지와 달라졌을 때의 영향을 적는다.
- 계산: 입력, 분자·분모, 단위, 기간, 제외 조건, 반올림 기준을 적는다.
- 제안: 실행 주체·조건·기대효과를 명시하되 미검증 효과를 실적처럼 표현하지 않는다.

## 파일 관리

원본은 보존한다. 작업 산출물과 실행 기록은 공개 툴킷과 분리한다. GitHub 사용 자료는 저장소 URL, 커밋 SHA 또는 미확인 표시, 파일 경로, 활용 범위, 라이선스를 남긴다. 출처 기록 자체가 라이선스 준수를 대신하지 않는다.

## 도구 출력

`csv_profile.py`와 `file_manifest.py`는 UTF-8 JSON을 stdout에 출력한다. 오류는 stderr와 종료 코드 2로 알린다. 정상 종료 코드는 0이며 manifest의 필수 파일 검사 실패는 1이다. JSON의 `schema_version`은 1이다. 파일 내용을 외부 서비스에 전송하지 않는다.
